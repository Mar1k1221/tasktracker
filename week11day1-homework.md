## Configuration

### Общие настройки приложения

| Параметр | Источник | Значение по умолчанию | Если значение не задано |
|---|---|---|---|
| `spring.application.name` | `application.properties` | `task-tracker` | Используется стандартное имя приложения |
| `DB_URL` | Переменная окружения | `jdbc:postgresql://localhost:5432/tasktracker_week8` | Используется локальный адрес PostgreSQL |
| `DB_USER` | Переменная окружения | `postgres` | Используется пользователь `postgres` |
| `DB_PASSWORD` | Переменная окружения | Нет | Приложение не сможет разрешить обязательную настройку и запуститься |
| `spring.jpa.hibernate.ddl-auto` | `application.properties` | `validate` | Будет применяться настройка Spring Boot / Hibernate по умолчанию |
| `spring.jpa.open-in-view` | `application.properties` | `false` | Будет применяться значение Spring Boot по умолчанию |

### Настройки JWT

| Параметр | Источник | Значение по умолчанию | Если значение не задано |
|---|---|---|---|
| `security.jwt.secret` | Переменная окружения `JWT_SECRET` | Нет | Приложение не запустится из-за ошибки разрешения и проверки настройки |
| `security.jwt.lifetime` | `application.properties` или переменная `SECURITY_JWT_LIFETIME` | `15m` | Используется значение `15m` из основного файла |

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `DB_URL` | Адрес подключения к PostgreSQL |
| `DB_USER` | Имя пользователя PostgreSQL |
| `DB_PASSWORD` | Пароль пользователя PostgreSQL |
| `JWT_SECRET` | Секрет для подписи и проверки JWT |
| `SECURITY_JWT_LIFETIME` | Переопределение времени жизни JWT |
| `SPRING_PROFILES_ACTIVE` | Выбор активного профиля: `dev` или `prod` |

**Примечание:** секреты не хранятся в репозитории. Они передаются приложению через переменные окружения.

### Проверка утечки JWT-секрета

При запуске приложения с коротким JWT-секретом (`short`) Spring Boot вывел значение секрета в диагностическом сообщении об ошибке конфигурации.

При отсутствии переменной `JWT_SECRET` в сообщении отображался placeholder `${JWT_SECRET}`, а не фактическое значение секрета.

**Вывод:** диагностические сообщения при ошибках конфигурации могут раскрывать секретные значения. Поэтому нельзя использовать реальные секреты в экспериментах с неправильной конфигурацией. 
Необходимо ограничивать доступ к логам и предусмотреть безопасное формирование сообщений об ошибках без вывода чувствительных значений.

### Почему у DB_URL есть значение по умолчанию, а у JWT_SECRET нет?

Для `DB_URL` допустимо значение по умолчанию, поскольку оно упрощает локальную разработку. Если переменная окружения не задана, приложение использует адрес локальной базы данных PostgreSQL.

Для `JWT_SECRET` значение по умолчанию недопустимо, поскольку этот секрет используется для криптографической подписи JWT. Если использовать известный или предсказуемый секрет, злоумышленник потенциально сможет создавать поддельные токены.

Поэтому JWT_SECRET должен передаваться извне и не должен храниться в репозитории или иметь небезопасное значение по умолчанию.
