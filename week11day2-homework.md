# Week 11 — Day 2. Что произойдёт без .dockerignore?

Файл `.dockerignore` нужен для исключения ненужных файлов и папок из контекста сборки Docker.

Если не создать `.dockerignore`, Docker будет передавать сборщику весь контекст сборки, включая файлы, которые не нужны для создания приложения.

Например, в нашем проекте TaskTracker это могут быть:

- `.env` — файлы с секретами, паролями и переменными окружения.
- `.git` — история Git и информация о репозитории.
- `target` — результаты предыдущих сборок Maven.
- `.idea` — настройки IntelliJ IDEA.
- `*.iml` — файлы конфигурации проекта IntelliJ.

**Какие проблемы могут возникнуть?**

1. **Безопасность.** Если использовать команду `COPY . .`, секреты из `.env` или другие конфиденциальные файлы могут попасть в Docker-образ.
2. **Увеличение размера.** Старые JAR-файлы, Git-история и другие ненужные данные могут увеличить размер контекста и образа.
3. **Замедление сборки.** Docker придётся передавать и обрабатывать больше файлов.
4. **Лишние данные.** В образ могут попасть настройки IDE, история разработки и другие файлы, которые не нужны для запуска приложения.

**Важное уточнение:** отсутствие `.dockerignore` не означает, что абсолютно все файлы автоматически окажутся внутри итогового Docker-образа. Они попадают в контекст сборки, а в образ переносятся инструкциями `COPY` или `ADD`.

В нашем Dockerfile мы используем выборочное копирование:

```dockerfile
COPY .mvn/ .mvn/
COPY mvnw pom.xml ./
COPY src/ src/
```

Поэтому `.env`, `.git` и `target` не копируются этими командами. Но без `.dockerignore` они всё равно будут передаваться в контекст сборки.

**Вывод:** `.dockerignore` помогает повысить безопасность, уменьшить объём передаваемых данных и ускорить сборку Docker-образа. Поэтому его рекомендуется создавать в каждом проекте, в котором используется Docker.
