## curl.exe -i http://localhost:8080/api/tasks - ожидаем 401 - так как пользователь не авторизован
curl.exe -i -u "user:пароль" http://localhost:8080/api/admin/tasks - ожидаем 403 потому что не хватает прав для выполнения данного запроса
curl.exe -i -u "user:МОЙ_ПАРОЛЬ" http://localhost:8080/api/tasks - ожидаем 200ок, так как пользователь авторизован и у него есть права для выполнения данного запроса

## Письменно объяснить эксперимент с порядком правил
Spring Security проверяет правила `requestMatchers` сверху вниз и применяет первое совпавшее правило. Если поставить широкое правило `requestMatchers("/api/**").permitAll()` перед `authenticated()`,
все запросы к `/api/**` будут доступны без авторизации, поэтому последующее ограничение не сработает для этих запросов.
Чтобы защита работала правильно, сначала нужно указывать более конкретные правила, а затем общие.

## При permitAll() первым запрос без авторизации получил 200.
   После перестановки правил запрос получил 401.
   Причина — Spring Security проверяет правила сверху вниз и применяет первое совпавшее правило.
